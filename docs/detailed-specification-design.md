## 3. 既存仕様の概要

### 3.1 公開学生プロフィール

ページ: `/students`

目的:

- 未ログインユーザーに学生DBの価値を見せる。
- 公開中の学生プロフィールの一部を表示する。
- 詳細閲覧はログイン導線へつなげる。

現行仕様:

- Supabase `students` から `publication_status = 'published'` の学生を取得する。
- 無料公開ページでは先出し3名のみ表示する。
- 表示項目は、表示名、学部、学年、出身、志望業界、属性タグ、キャッチコピー、プロフィール概要、画像、動画。
- 詳細プロフィール閲覧は `/login?next=/members/students` へ誘導する。

### 3.2 企業会員DB

ページ: `/members/students`

目的:

- 有効な企業会員が、学生の詳細プロフィールを閲覧する。
- 企業から学生への面談リクエストを送信する。

現行仕様:

- 未ログインの場合は `/login?next=/members/students` へ redirect。
- 企業の `membership_status` が `active` または `trial` の場合のみ閲覧可能。
- 閲覧不可の場合は `/membership-inactive` へ redirect。
- `students` と `student_member_profiles` を取得し、学生フィードとして表示。
- 面談リクエストフォームから `interview_requests` に登録する。

### 3.3 運営管理画面

ページ:

- `/admin`
- `/admin/students`
- `/admin/companies`
- `/admin/requests`

目的:

- 運営が学生、企業、会員状態、面談リクエストを管理する。

現行仕様:

- 管理者は `admin_users` に登録されたAuthユーザーのみ。
- 学生の作成・編集・公開状態管理が可能。
- 企業の作成・編集・会員ステータス管理が可能。
- 企業ログイン設定リンクを発行できる。
- 面談リクエストのステータス変更が可能。
- 学生メディアは `student-media` bucket にアップロードできる。

## 5. 直近ヒアリングで確定した新方針

### 5.1 サービスの位置付け

今回の主サービスは、アンバサダー事業ではなく、一般的な人材紹介サービスとして進める。

### 5.2 学生から企業への連絡方法

初期実装では、学生は企業メールアドレスへ直接連絡する。

初期実装では以下を作らない。

- 応募フォーム
- 応募管理
- サイト内DM
- 近世側で応募後に確認して企業へつなぐフロー

### 5.3 学生プロフィール登録・編集

初期実装では、学生プロフィールは近世側で登録・管理する。

将来的に母集団が300名を超えた段階で、学生自身がプロフィールを編集し、近世側が確認後に掲載する形を検討する。

### 5.4 企業案件情報の管理

企業ロゴをクリックした先に簡単な求人案件情報を表示する。

求人案件情報は、企業側が登録するのではなく、近世側の管理画面から登録・編集できる形にする。

### 5.5 企業側の案件登録

初期実装では、企業側が自分で案件を登録・編集する機能は作らない。

## 6. 新しいサービス全体像

### 6.1 初期リリースの主導線

初期リリースでは、以下の導線を主導線とする。

1. 学生がサイトへアクセスする。
2. 学生が企業一覧を見る。
3. 学生が企業ロゴまたは企業カードをクリックする。
4. 学生が企業詳細・求人案件情報を見る。
5. 学生が掲載されている企業メールアドレスへ直接連絡する。

### 6.2 近世側の運用導線

1. 近世が学生情報を登録・管理する。
2. 近世が学生プロフィールの公開状態を管理する。
3. 近世が企業情報を登録・管理する。
4. 近世が求人案件情報を登録・管理する。
5. 近世が必要に応じて掲載企業・求人案件の公開状態を変更する。

### 6.3 企業側の導線

初期実装では、企業側は自分で案件登録しない。

企業は、学生からのメール連絡を受け取る。

既存の企業会員DB機能は残すが、新しい学生向け企業一覧・求人案件導線とは別機能として扱う。

## 7. ユーザー種別と権限

### 7.1 一般学生 / 未ログインユーザー

初期実装でできること:

- 企業一覧を見る。
- 企業詳細を見る。
- 求人案件情報を見る。
- 企業メールアドレス宛に直接連絡する。
- 公開学生プロフィールを見る。

初期実装でできないこと:

- 自分のプロフィールをサイト上で編集する。
- サイト内応募フォームを送る。
- サイト内DMを送る。
- 応募状況をサイト内で管理する。

### 7.2 企業会員

既存機能としてできること:

- ログインする。
- 会員ステータスが有効な場合、学生詳細DBを見る。
- 面談リクエストを送る。

新しい企業案件掲載機能では、初期実装でできないこと:

- 企業側で求人案件を登録・編集する。
- 学生からのメール連絡をサイト内で管理する。

### 7.3 近世管理者

初期実装でできること:

- 学生プロフィールを登録・編集する。
- 学生プロフィールの公開状態を管理する。
- 企業情報を登録・編集する。
- 求人案件情報を登録・編集する。
- 企業情報と求人案件情報の公開状態を管理する。
- 既存の企業会員ステータスを管理する。

### 7.4 将来の学生ユーザー

第2フェーズ以降で検討する。

できるようにする可能性があること:

- 学生ログイン
- 学生マイページ
- 自分のプロフィール編集
- 近世承認待ちステータスの確認
- 登録内容の差し戻し対応

### 9.3 RLS 方針

`job_posts`:

- `published` の求人案件は anon / authenticated が閲覧可能。
- 作成・編集・削除は管理者のみ。

`companies` の公開項目:

- `public_status = 'published'` の企業を一覧表示対象にする。
- 既存の企業会員レコードと兼用する場合、学生向けに公開してよい項目のみページへ返す。
- `contact_email` と `public_contact_email` を混同しない。

## 10. マーケティングページ仕様

### 10.1 TOPページ

直近ヒアリング反映後の主訴求:

- メインコピー: `学歴ではなく実歴で戦え`
- サブコピー: `実戦経験を積んだ学生と企業をつなぎ、採用市場のミスマッチを減らす`
- 主対象: 企業向け寄り。ただし学生向け導線も残す。

現在残っている仮要素:

- 300名以上
- 50社以上
- 掲載プロジェクト24件
- 仮ロゴ
- 仮事例

実装方針:

- 実数が確定しないものは削除または予定表記にする。
- 仮ロゴは本物の協賛企業のように見せない。
- 事例はヒアリング済みの3件に差し替える。

### 10.2 サービス利用の流れ

掲載予定:

1. `無料登録`
   - `自分の現在地を知る`
2. `キャリア面談`
   - `ビジョンから逆算して進路を考える`
3. `企業紹介・イベント参加`
   - `納得できる意思決定をする`

補足ブロック:

- `なぜ近世の学生は選ばれるのか？`
- `ビジョンを描く`
- `実戦で磨く`
- `理想の企業と出会う`

仕様上の解釈:

- `無料登録` は初期実装では学生ログイン登録ではなく、近世側で学生DB登録・管理する工程として扱う。
- 学生ログイン・プロフィール自己編集は第2フェーズ以降。
- `現在地を知る` はキャリア面談で整理する。

### 10.3 料金ページ

ヒアリング反映予定:

- プラットフォーム利用料
  - 単月プラン: 月額 5,500円
  - 年間プラン: 月額 3,300円
- 人材紹介料
  - 採用成功報酬: ¥1,000,000

要確認:

- 税込 / 税別
- 年間プランの割引表記
- 成功報酬の発生条件

### 10.4 協賛企業 / 企業一覧

既存の `sponsors_list.html` は協賛企業一覧として存在する。

新しい学生向け企業一覧は、協賛企業一覧とは役割が異なる。

整理案:

- `sponsors_list.html`: 協賛企業・パートナー掲載
- `/companies`: 学生向け企業一覧・求人案件導線

混同を避けるため、求人案件を表示する学生向け企業一覧は Next.js 側に新設する。

## 14. 非機能要件

### 14.1 セキュリティ

- Supabase service role key はブラウザに出さない。
- 管理画面は `admin_users` のみアクセス可能。
- 学生詳細プロフィールは不要なページに返さない。
- 企業ログイン用メールと学生向け公開メールを分ける。
- 公開対象の企業・求人案件のみ anon に返す。
- 学生本人の掲載同意、企業メール公開許可は運用上確認する。

### 14.2 レスポンシブ

- 390px前後のスマホ表示を重視する。
- 企業一覧カード、求人案件カード、メールボタンはスマホで押しやすくする。
- 長い企業名、求人タイトル、メールアドレスがはみ出さないようにする。

### 14.3 運用

- 近世管理者が日常的に更新できることを優先する。
- 求人案件は `draft` で下書き保存できる。
- 掲載終了済み求人は削除せず `archived` にする。
- 公開メールアドレスの誤掲載を防ぐため、登録画面上で確認しやすくする。

### 14.4 法務・許認可

一般的な人材紹介サービスとして進める場合、紹介料、学生情報、企業連絡先公開、職業紹介に関する許認可・契約・個人情報の取り扱いは、近世側で別途確認する。

本仕様書では法務判断は行わない。

## 18. 注意点

- 既存資料の一部は「企業が学生DBを見る」前提で書かれているため、新しい学生向け企業一覧・求人案件導線とは別物として扱う。
- `interview_requests` は既存機能として残すが、今回の初期主導線では使わない。
- `companies.contact_email` は企業ログインや担当者管理に使っているため、学生向け公開メールには `public_contact_email` を使う。
- `sponsors_list.html` と学生向け企業一覧は目的が異なるため、求人案件導線は Next.js 側の `/companies` に新設する。
- 学生プロフィール自己編集は将来要件として残すが、初期実装には含めない。

作成日: 2026-07-07  
対象: KINSEI 公式サイト / 学生ログイン / 企業一覧 / 求人情報 / プロフィール付き企業連絡  
ステータス: 実装前の正本仕様

## 0. この仕様書の位置付け

本仕様書は、直近の方針変更を反映した実装用の正本とする。

以前の整理では、初期実装を「学生ログインなし」「企業メールアドレスへの直接 `mailto`」としていた。しかし、学生が企業へ連絡する際に、近世側で登録済みの学生プロフィール情報をセットで送る必要が出てきたため、初期実装から学生ログインを含める。

ただし、初期実装では学生自身によるプロフィール編集までは含めない。近世側が学生情報を登録し、学生はログイン後に自分のプロフィールを確認し、その情報を添えて企業へ連絡する。

## 1. 結論

初期リリースは以下の仕様で進める。

- 学生ログインを作る。
- 学生プロフィールは初期は近世側が登録・管理する。
- 学生はログイン後、自分の登録プロフィールを確認できる。
- 学生は企業一覧・企業詳細・求人情報を閲覧できる。
- 学生はログイン後、登録プロフィール情報を反映したメール本文を生成し、企業メールアドレスへ直接連絡できる。
- サイト側では、学生がどの企業・求人へ連絡導線を利用したかを履歴として保存する。
- 初期実装では、学生によるプロフィール編集、企業側管理画面、サイト内DM、自動マッチング、決済は含めない。

## 2. なぜ学生ログインが必要か

企業へ送る学生情報は個人情報であるため、ログインなしで自動的に扱うのは危険である。

学生ログインにより、以下を担保する。

- 本人がログインしていること。
- 自分のプロフィール情報を確認したうえで企業に送ること。
- 企業へ情報共有することへの同意を取ること。
- どの企業・求人に連絡したかを記録すること。
- 将来、プロフィール編集や応募管理へ拡張できること。

## 4. ユーザー種別と権限

### 4.1 未ログインユーザー

できること:

- TOPや料金ページなどの公開ページを見る。
- 公開学生プロフィール `/students` を見る。
- 企業一覧 `/companies` を見る。
- 企業詳細・求人情報の一部を見る。

できないこと:

- 学生本人のプロフィールを見る。
- プロフィール付きで企業へ連絡する。
- 連絡履歴を見る。

### 4.2 学生ユーザー

できること:

- 学生ログインする。
- 自分のプロフィールを確認する。
- 企業一覧を見る。
- 企業詳細を見る。
- 求人情報を見る。
- 登録プロフィール情報を反映したメール本文を生成する。
- 企業へメール連絡する前に、共有内容を確認する。
- 自分の連絡履歴を見る。

初期実装でできないこと:

- 自分のプロフィールを編集する。
- プロフィール公開申請を出す。
- サイト内DMを送る。
- 企業とのやり取りをサイト内で完結する。

### 4.3 企業会員

既存機能としてできること:

- 企業ログインする。
- 会員ステータスが有効な場合、会員限定学生DBを見る。
- 面談リクエストを送る。

今回の学生向け企業連絡機能では初期実装でできないこと:

- 企業側で求人情報を登録・編集する。
- 学生からの連絡履歴を管理画面で見る。
- サイト内で学生に返信する。

### 4.4 近世管理者

できること:

- 学生プロフィールを登録・編集する。
- 学生にログイン用アカウントを紐づける。
- 学生へパスワード設定リンクを共有する。
- 企業情報を登録・編集する。
- 求人情報を登録・編集する。
- 学生から企業への連絡履歴を見る。
- 公開状態を管理する。

## 5. 初期リリースの主導線

### 5.1 学生登録・ログイン導線

```text
近世管理者が学生情報を登録
  ↓
近世管理者が学生用Authユーザーを作成または紐づけ
  ↓
学生へパスワード設定リンクを共有
  ↓
学生がパスワード設定
  ↓
学生が /student/login からログイン
  ↓
学生が /student/profile で自分のプロフィールを確認
```

### 5.2 企業連絡導線

```text
学生がログイン
  ↓
/companies で企業一覧を見る
  ↓
/companies/[companyId] で企業詳細・求人情報を見る
  ↓
「プロフィール情報を添えて連絡する」を押す
  ↓
共有されるプロフィール情報とメール本文を確認
  ↓
同意チェック
  ↓
学生本人のメールアプリを開く
  ↓
企業メールアドレス宛に送信
  ↓
サイト側に連絡導線利用履歴を保存
```

初期実装では、学生本人のメールアドレスから企業へ直接送る形を維持する。つまり、システムが企業へ自動送信するのではなく、ログイン済み学生のプロフィール情報を使ってメール本文を生成する。

この仕様により、先方が希望している「学生が企業メールアドレスへ直接連絡」と、今回追加で必要になった「近世登録の学生情報をセットで送る」を両立する。

## 6. 画面仕様

### 6.1 学生ログイン

想定URL:

- `/student/login`

仕様:

- Supabase Auth のメールアドレス + パスワードでログインする。
- ログイン成功後は `/student/profile` へ遷移する。
- `next` パラメータがある場合は、ログイン後に元の企業詳細や求人詳細へ戻す。
- 企業ログイン `/login` とは分ける。

注意:

- 同じ Supabase Auth を使うが、学生ユーザーは `students.auth_user_id` に紐づく。
- 企業ユーザーは `companies.auth_user_id` に紐づく。
- 管理者は `admin_users.auth_user_id` に紐づく。

### 6.2 学生マイページ

想定URL:

- `/student/profile`

目的:

- 学生が近世登録済みのプロフィール内容を確認する。
- 企業へ送られる情報の内容を理解できるようにする。

表示項目:

- 氏名
- 表示名
- 大学・学部
- 学年
- 居住地または活動エリア
- 志望業界
- 属性タグ
- キャッチコピー
- プロフィール概要
- キャリア軸
- 価値観
- 意思決定軸
- 将来像
- プロフィール画像
- 動画URL

初期実装では編集フォームは出さない。

誤りがある場合の導線:

- `登録内容の修正を依頼する`
- 初期は `mailto:` または問い合わせ先への導線でよい。

### 6.3 学生向け企業一覧

### 6.6 プロフィール付きメール確認画面またはモーダル

想定:

- 企業詳細ページ内のモーダル
- または `/companies/[companyId]/contact`
- 求人別にする場合は `/jobs/[jobId]/contact`

表示する内容:

- 送信先企業名
- 送信先メールアドレス
- 対象求人
- メール件名
- メール本文プレビュー
- 企業へ共有されるプロフィール項目
- 同意チェック

同意文言:

```text
近世に登録されている私のプロフィール情報を、選択した企業への連絡内容に含めることに同意します。
```

ボタン:

- `メールアプリを開く`

クリック時の処理:

1. サーバー側でログイン中の学生を確認する。
2. 学生プロフィール、企業、求人情報を取得する。
3. 共有対象プロフィールのスナップショットを作る。
4. `student_company_contacts` に履歴を保存する。
5. `mailto:` URL を生成する。
6. 学生のメールアプリを開く。

注意:

- `mailto:` は実際の送信完了までは検知できない。
- 初期実装の履歴は「メール作成導線を利用した履歴」として扱う。
- 送信完了や到達確認まで必要な場合は、Resend 等のメール送信サービス導入が別途必要。

## 9. RLS / アクセス制御

### 9.1 学生ユーザー判定

学生ログインユーザーは以下で判定する。

```text
students.auth_user_id = auth.uid()
```

### 9.2 `students`

- `publication_status = 'published'` の公開項目は anon / authenticated が閲覧可能。
- 学生本人は自分の `students` レコードを閲覧可能。
- 管理者は全件管理可能。
- 学生本人による更新は初期実装では不可。

### 9.3 `student_member_profiles`

- 既存どおり有効な企業会員は会員限定閲覧可能。
- 学生本人は自分の詳細プロフィールを閲覧可能。
- 管理者は全件管理可能。
- 学生本人による更新は初期実装では不可。

### 9.4 `companies`

- `public_status = 'published'` の公開企業情報は anon / authenticated が閲覧可能。
- 企業ログイン用の担当者情報は学生向けページへ返さない。
- 管理者は全件管理可能。

### 9.5 `job_posts`

- `publication_status = 'published'` かつ紐づく企業が `public_status = 'published'` の求人は閲覧可能。
- 作成・編集・削除は管理者のみ。

### 9.6 `student_company_contacts`

- 学生本人は自分の履歴のみ insert / select 可能。
- 管理者は全件閲覧可能。
- 未ログインユーザーは insert 不可。
- 企業ユーザーは初期実装では閲覧不可。

## 10. メール本文仕様

### 10.1 件名

求人単位の場合:

```text
【KINSEI】{求人タイトル}への応募について / {学生氏名}
```

企業単位の場合:

```text
【KINSEI】企業掲載情報を拝見してのご連絡 / {学生氏名}
```

### 10.2 本文

```text
{企業名}
ご担当者様

KINSEIの掲載情報を拝見し、ご連絡いたしました。

■ 学生情報
氏名: {real_name}
大学・学部: {faculty}
学年: {grade}
活動エリア: {location}
志望業界: {desired_industries}

■ 自己紹介
{profile_summary}

■ キャリア軸
{career_axis}

■ 興味を持った求人
{job_title}

■ 連絡先
メール: {student_login_email}

ご確認のほど、よろしくお願いいたします。
```

初期実装では、本文に入れる項目を固定する。詳細すぎる価値観情報や深掘り回答は、本人確認画面で見せたうえで、共有対象に含めるか判断する。

`mailto:` は環境によってURL長の制限を受けるため、メール本文は長くしすぎない。初期実装では、本文は目安として1,500〜2,000文字以内に収める。詳細プロフィールの全量は `profile_snapshot` に保存できるが、企業メール本文へ入れる項目は必要最低限に絞る。

実装時は、サーバー側でログイン・同意・対象企業・対象求人を検証し、履歴保存後に `mailto:` URL をクライアントへ返す。クライアント側で `window.location.href` などによりメールアプリを開く。

## 16. 受け入れ条件

- 学生が `/student/login` からログインできる。
- 学生が `/student/profile` で自分のプロフィールを確認できる。
- 学生は他の学生の非公開プロフィールを閲覧できない。
- 管理者が学生にAuthユーザーを紐づけられる。
- 管理者が企業公開情報を登録・編集できる。
- 管理者が求人情報を登録・編集できる。
- 公開中の企業だけが `/companies` に表示される。
- 公開中の求人だけが企業詳細に表示される。
- 未ログインで連絡CTAを押すと学生ログインへ誘導される。
- ログイン済み学生は、プロフィール情報入りのメール本文を確認できる。
- 同意チェック後にメールアプリを開ける。
- 連絡導線利用履歴が `student_company_contacts` に保存される。
- 既存の `/login`、`/members/students`、`/admin` が壊れていない。
- スマホ390px前後でログイン、プロフィール、企業一覧、企業詳細、連絡CTAが崩れない。
- `npm run build` が通る。

## 18. 注意点

- 「学生ログインあり」になったため、以前の「学生ログインなし」前提の仕様は使わない。
- `mailto:` では送信完了を検知できない。履歴は送信完了ではなく「メール作成導線を利用した履歴」として扱う。
- 本当に企業への自動送信・到達管理まで行う場合は、Resend 等のメール送信サービスと `student_applications` への仕様拡張が必要。
- 企業ログインと学生ログインは同じSupabase Authを使ってもよいが、画面と権限は分離する。
- 学生本人が見るプロフィールと、企業へメール本文として共有するプロフィール項目は一致させすぎない。共有対象は必要最低限から始める。
- 個人情報共有の同意文言、職業紹介に関する契約・許認可・個人情報管理は近世側で別途確認する。

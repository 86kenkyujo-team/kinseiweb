# 運営専用ページ 要件定義書

作成日: 2026-05-05  
対象機能: 運営専用管理画面  
対象サイト: 近世 KINSEI 公式 HP / 企業会員限定 学生データベース

## 1. 目的

運営担当者が Supabase やコードを直接触らずに、学生情報、企業情報、契約状況メモ、面談リクエストを管理できるようにする。

この管理画面は決済システムではない。
契約やサブスクリプションは外部で行い、運営が確認した結果を本システムに登録する。

## 2. 基本方針

- 運営担当者はエンジニアではない前提で設計する
- 企業アカウントは 1 社 1 アカウントで始める
- 企業登録は運営登録制とする
- 企業のログイン用メールアドレスは、企業側が既に保有している担当者メールアドレスを使う
- 本システムはメールアドレスを発行しない
- 企業パスワードは企業担当者が招待リンクまたはパスワード設定リンクから自分で設定する
- 契約、サブスクリプション、支払い処理は本システム内では行わない
- 管理画面上の契約情報は、外部で確認した状況を記録する台帳として扱う

## 3. 画面構成

想定 URL:

- `/admin/login`
- `/admin`
- `/admin/students`
- `/admin/students/new`
- `/admin/students/[studentId]/edit`
- `/admin/companies`
- `/admin/companies/new`
- `/admin/companies/[companyId]`
- `/admin/requests`

企業会員向け画面 `/members/students` とは完全に分離する。

## 4. 管理者ログイン

運営管理者だけが `/admin` にアクセスできる。

要件:

- メールアドレスとパスワードでログインする
- 管理者権限を持つユーザーだけが管理画面に入れる
- 企業アカウントでは管理画面に入れない
- 未ログイン時は `/admin/login` にリダイレクトする
- 管理者判定は `admin_users` テーブル、または Supabase Auth の custom claims で行う

## 5. ダッシュボード

`/admin` では運営が今日見るべき情報をまとめる。

表示項目:

- 公開中学生数
- 下書き学生数
- 有効企業数
- 支払い確認待ち企業数
- 新規面談リクエスト数
- 最近更新された学生
- 最近登録された企業
- 次回確認日が近い企業

## 6. 学生管理

### 6.1 学生一覧

表示項目:

- 表示名
- 本名
- 学部、学年
- 志望業界
- 公開ステータス
- 画像登録有無
- 動画登録有無
- 最終更新日

フィルター:

- 公開中
- 下書き
- アーカイブ
- 志望業界
- 学年

### 6.2 学生登録・編集

公開情報:

- 表示名
- イニシャル
- 学部
- 学年
- 地域
- 属性タグ
- 志望業界
- キャッチコピー
- 公開プロフィール概要
- TikTok URL
- プロフィール画像 URL
- 紹介動画 URL
- 公開ステータス

会員限定情報:

- 本名
- 価値観
- 思考スタイル
- キャリアの軸
- 志望理由の深掘り
- 意思決定の軸
- 将来像
- 面談希望条件
- 深掘り Q&A

### 6.3 公開ステータス

- `draft`: 下書き
- `published`: 公開中
- `archived`: 非公開、掲載終了

`published` の学生だけが公開 DB と企業会員 DB に表示される。
公開前には必須項目の入力チェックを行う。

## 7. 企業管理

### 7.1 企業一覧

表示項目:

- 企業名
- 担当者名
- 担当者メールアドレス
- 会員ステータス
- プラン名
- 契約開始日
- 契約終了日
- 次回確認日
- 面談リクエスト数
- 最終更新日

フィルター:

- 契約中
- トライアル
- 支払い確認待ち
- 停止中
- 解約済み
- 次回確認日が近い

### 7.2 企業登録

運営が外部で契約やサブスクリプション状況を確認した後、企業情報を登録する。

入力項目:

- 企業名
- 担当者名
- 担当者メールアドレス
- 会員ステータス
- プラン名
- 契約開始日
- 契約終了日
- 次回確認日
- 契約状況メモ
- 運営メモ

登録時の処理:

1. `companies` に企業情報を作成する
2. Supabase Auth に担当者メールアドレスのユーザーを作成する
3. `companies.auth_user_id` に Auth ユーザー ID を紐づける
4. 管理画面にログイン設定リンクを表示し、運営が既存チャットで企業担当者へ共有する

### 7.3 パスワード設定

企業担当者が自分でパスワードを設定する。

要件:

- 運営は企業パスワードを入力しない
- 運営は企業パスワードを閲覧できない
- ログイン設定リンクには有効期限を設ける
- リンク期限切れ時は運営が再発行できる
- 企業担当者がパスワードを忘れた場合はリセット導線で対応する

### 7.4 会員ステータス

- `trial`: トライアル中、閲覧可
- `active`: 契約中、閲覧可
- `past_due`: 支払い確認待ち、閲覧不可
- `suspended`: 停止中、閲覧不可
- `cancelled`: 解約済み、閲覧不可

ステータス変更は即時で企業側の閲覧可否に反映する。
契約やサブスクリプション自体の処理は外部で行い、管理画面では確認結果だけを登録する。

## 8. 面談リクエスト管理

表示項目:

- リクエスト日時
- 企業名
- 担当者名
- 対象学生
- リクエスト理由
- 希望形式
- 希望時期
- 対応ステータス
- 運営メモ

ステータス:

- `new`: 新規
- `reviewing`: 確認中
- `introduced`: 接続済み
- `declined`: 見送り
- `closed`: 完了

運営操作:

- ステータス変更
- 運営メモ追加
- 学生への確認状況を記録
- 企業への返信状況を記録

## 9. セキュリティ要件

- 管理画面は管理者だけがアクセスできる
- 企業アカウントでは `/admin` に入れない
- Supabase の `service_role` キーはサーバー側だけで使う
- ブラウザに管理用キーを出さない
- 学生の本名や詳細情報は管理者と有効企業のみ閲覧できる
- 企業パスワードは保存表示しない
- 企業アカウント作成、停止、ステータス変更は操作ログを残す
- 招待リンク、パスワード設定リンクは期限付きにする
- 企業担当者メールアドレスの変更時は確認を挟む

- `admin_users`
- `admin_activity_logs`
- `company_status_logs`
- `student_publication_logs`

## 11. 実装優先順位

### Phase 1

- 管理者ログイン
- 企業一覧
- 企業登録
- 企業ステータス変更
- 招待リンクまたはパスワード設定リンク送信
- 学生一覧
- 学生追加、編集
- 学生公開、非公開切り替え

### Phase 2

- 面談リクエスト管理
- ダッシュボード
- 変更履歴
- 運営メモ
- 契約日、次回確認日管理

### Phase 3

- 契約確認日の通知
- 支払い確認待ち企業のアラート
- ログイン設定リンク再発行
- 面談リクエスト通知メール
- CSV 出力
- 学生情報の一括登録

## 12. 現時点の決定事項

- 契約やサブスクリプションは本システム内で処理しない
- 管理画面では外部で確認した契約状況を登録、確認する
- 企業アカウントは 1 社 1 アカウント
- 企業登録は運営登録制
- メールアドレスは企業側が既に保有している担当者メールアドレスを使う
- パスワードは企業担当者が自分で設定する
